# UV RecSys

Учебный проект по рекомендациям фильмов для [HSE RecSys Challenge 2026](https://www.kaggle.com/competitions/hse-rec-sys-challenge-2026).

По истории оценок нужно предложить каждому пользователю **10 фильмов**. Метрика соревнования — **Recall@10**. В проекте последовательно проверены популярность, ItemKNN, EASE и SASRec.

**Финальная модель — SASRec. Результат на Kaggle — 0,2847; локальный Recall@10 — 0,141546.** Пройдены все три бейзлайна преподавателя, включая `baseline_5 = 0,0821`.

Весь код, параметры, графики и результаты выполнения находятся в [hse_recsys.ipynb](hse_recsys.ipynb). Решение запускается одним полным выполнением тетрадки. Описание гипотез и экспериментов собрано ниже.

## Данные

| Файл | Содержимое |
|---|---|
| `events.csv` | История взаимодействий: `user_id`, `item_id`, `rating`, `timestamp` |
| `user_features.csv` | Каталог пользователей, пол и возраст |
| `item_features.csv` | Каталог фильмов и жанровые признаки |
| `submission_sample.csv` | Пользователи для рекомендаций и образец формата сабмита |

В данных **894 149 событий**, **6 040 пользователей** и **3 706 фильмов**. История есть у 3 690 фильмов. Минимальная длина истории пользователя — 14 событий, медиана — 84,5.

Для обучения используются взаимодействия пользователей с фильмами. Любая оценка, включая низкую, считается фактом взаимодействия; порог по `rating` не применяется. Пол, возраст и жанры в обучение не включаются. Файлы признаков используются для получения полного списка пользователей и фильмов.

Идентификаторы читаются как строки и переводятся во внутренние индексы. При экспорте восстанавливаются исходные ID. `timestamp` используется для порядка событий внутри пользователя: его значения похожи на позиции в истории, поэтому в решении он не трактуется как глобальное Unix-время.

## Локальная валидация

Для каждого пользователя события сортируются по `timestamp`. **Последние 20% событий, с округлением вверх, откладываются в validation**, остальные используются для обучения:

| Часть | События | Пользователи |
|---|---:|---:|
| Train | 712 916 | 6 040 |
| Validation | 181 233 | 6 040 |

Популярность, сходства фильмов, веса EASE и обучающие последовательности SASRec рассчитываются только по train. Все модели сравниваются на одном разбиении.

Для пользователя метрика равна доле отложенных фильмов, попавших в первые 10 рекомендаций:

$$\operatorname{Recall@10}(u)=\frac{|\operatorname{Top10}(u)\cap\operatorname{Target}(u)|}{|\operatorname{Target}(u)|}.$$

Итоговая локальная метрика — среднее по пользователям с непустым target. Ранжирование проводится по полному каталогу, без выборки негативных примеров. Уже известные фильмы исключаются по всей доступной истории пользователя: на валидации — по train, при финальном предсказании — по всему `events.csv`. В рекомендации не попадают повторы.

Это локальная схема оценки. Состав и разбиение скрытого теста Kaggle могут отличаться, поэтому локальные значения и публичный score напрямую не сопоставляются.

## Гипотезы и результаты экспериментов

В таблице приведены локальные результаты приложенной выполненной тетрадки и результаты отправленных ранее сабмитов на Kaggle. Прочерк означает, что отдельный Kaggle score для этого подхода не зафиксирован.

| Этап | Гипотеза | Локальный Recall@10 | Kaggle Recall@10 |
|---|---|---:|---:|
| H0: популярность | Популярные фильмы дают рабочую точку отсчёта | 0,036167 | — |
| H1: ItemKNN | Сходство фильмов по общим пользователям улучшает персонализацию | 0,055767 | 0,0594 |
| H2: EASE, λ = 1000 | Совместно обученные связи между фильмами улучшают результат | 0,065038 | 0,0860 |
| **H3: SASRec — финальная модель** | **Последовательность взаимодействий содержит дополнительный полезный сигнал** | **0,141546** | **0,2847** |

### H0 — популярность

Рекомендуем фильмы с наибольшим числом взаимодействий в train, исключая известные пользователю. Получаем простой ориентир: **0,036167** локально.

### H1 — ItemKNN

Переходим к персонализации: считаем cosine similarity фильмов по бинарной матрице взаимодействий, применяем `shrinkage = 10` и оставляем **100 соседей** каждого фильма. Оценка кандидата — сумма сходств с фильмами из истории пользователя.

Локальный Recall@10 вырос до **0,055767**, на Kaggle получено **0,0594**. Сходство фильмов оказалось полезнее общей популярности.

### H2 — EASE и регуляризация

Вместо отдельных соседских сходств обучаем общую матрицу линейных связей между фильмами. EASE восстанавливает бинарную матрицу взаимодействий с L2-регуляризацией; диагональ матрицы весов равна нулю, чтобы фильм не предсказывал сам себя.

На том же validation проверены пять значений регуляризации:

| λ | Локальный Recall@10 |
|---:|---:|
| 100 | 0,061258 |
| 300 | 0,063336 |
| **1000** | **0,065038** |
| 3000 | 0,064884 |
| 10000 | 0,062299 |

Выбрано **λ = 1000** по локальной метрике. Сабмит дал **0,0860** на Kaggle и превысил `baseline_5 = 0,0821`.

### H3 — SASRec, финальный подход

Предыдущие модели используют набор фильмов пользователя без учёта порядка. SASRec обучается предсказывать следующий фильм по предшествующей последовательности. Использована архитектура `replay.nn.sequential.SasRec` из **RePlay 0.22.0** с циклом обучения на PyTorch.

Causal attention ограничивает доступ к последующим позициям. Функция потерь — полная cross-entropy по каталогу. Длинные истории разбиваются на перекрывающиеся окна; padding и переход от padding к первому фильму не участвуют в loss. Для предсказания используются последние 100 известных событий, а просмотренное исключается по всей известной истории. Фильмы без обучающих событий получают минимальный score.

| Параметр | Значение |
|---|---:|
| Seed | 42 |
| Максимальная длина последовательности | 100 |
| Шаг обучающих окон | 50 |
| Размерность эмбеддингов | 64 |
| Attention heads / блоки | 2 / 2 |
| Dropout | 0,2 |
| Batch size: обучение / предсказание | 128 / 256 |
| Оптимизатор | AdamW |
| Learning rate | 0,001 |
| Weight decay | 0,00001 |
| Gradient clipping | 1,0 |
| Максимум эпох / patience | 50 / 8 |
| Mixed precision | Включена на GPU |

На train сформировано **13 640 окон**. Проведены 50 эпох с оценкой после каждой; лучшей стала **48-я эпоха** с Recall@10 = **0,141546**. По сравнению с EASE локальная метрика выросла более чем вдвое, поэтому SASRec выбран финальной моделью.

Затем SASRec инициализирован заново с тем же seed и обучен **48 эпох на всех 894 149 событиях**. Validation возвращается в обучение только на этом этапе. Именно эта модель формирует финальный `submission.csv`; ансамблирование при экспорте не применяется.

В выполненной тетрадке подбор эпохи занял около **309 секунд**, финальное обучение — около **152 секунд** на Tesla T4, без учёта установки зависимостей. Итоговый зафиксированный Kaggle score — **0,2847**.

## Как воспроизвести

### В Kaggle

1. Создать Notebook и импортировать `hse_recsys.ipynb`.
2. Через **Add Input** подключить данные соревнования: в одной папке должны быть все четыре CSV.
3. В настройках включить **GPU** и **Internet** для установки зависимостей.
4. Выполнить **Restart Kernel and Run All**.
5. После завершения скачать `outputs/final_artifacts.zip`. Для отправки в соревнование используется файл `submission.csv` из архива.

Путь к данным определяется автоматически. Если найдено несколько копий датасета, нужно указать нужную папку в `DATA_DIR` в начале тетрадки.

### Локально

Разместить тетрадку в корне проекта, а четыре CSV — в `data/`. Открыть тетрадку в Jupyter и выполнить все ячейки. Нужны базовые библиотеки NumPy, pandas, SciPy, Matplotlib, threadpoolctl и IPython, а также PyTorch **≥ 2.5** с поддержкой CUDA. Зависимости SASRec устанавливаются из самой тетрадки.

По умолчанию запуск требует GPU (`require_cuda=True`). CPU можно разрешить в `CONFIG`, но полное обучение на нём будет медленнее.

### Окружение сохранённого запуска

Использованы **Tesla T4**, Python **3.13.15**, PyTorch **2.11.0+cu128**, CUDA **12.8**, RePlay **0.22.0**, Lightning **2.5.6**, torchmetrics **1.8.2**, NumPy **2.1.3**, pandas **2.3.3** и SciPy **1.16.3**. Тетрадка фиксирует версии RePlay, Lightning и torchmetrics, сохраняя установленный в среде CUDA PyTorch.

Текущие версии, параметры и SHA-256 исходных CSV записываются в `run_info.json`. В приложенном повторном выполнении итоговый CSV **побайтово совпал** с исходным успешным сабмитом: ячейка сравнения SHA-256 вывела `True`.

SHA-256 успешного `submission.csv`:

```text
c6ef549014336f93ff099cd6e0fd85a806a0155fca5ec0c6a051999db1c7a443
```

В другой версии GPU-окружения возможны небольшие численные отличия: PyTorch предупреждает о недетерминированной реализации memory-efficient attention. Новый CSV можно сверить по хешу; при несовпадении его Kaggle score определяется отдельной отправкой.

## Результаты и сохранённые веса

Полный запуск создаёт следующие файлы в `outputs/`:

| Файл | Назначение |
|---|---|
| `submission.csv` | Финальные рекомендации SASRec для отправки в Kaggle |
| `sasrec_full.pt` | Финальная модель, обученная 48 эпох на полной истории в сохранённом запуске |
| `sasrec_validation_best.pt` | Лучшая модель на train-части для локальной оценки |
| `sasrec_full.history.csv` | Loss и время эпох финального обучения |
| `sasrec_validation_best.history.csv` | Loss, Recall@10 и время эпох при подборе числа эпох |
| `experiments.csv` | Локальные метрики всех проверенных моделей и значений λ |
| `run_info.json` | Конфигурация, версии, метрики, выбранная эпоха и хеши данных и сабмита |
| `final_artifacts.zip` | Архив перечисленных результатов для скачивания из Kaggle |

`submission.csv` содержит **6 040 строк**, по одной на пользователя из sample, в исходном порядке. Колонки — `user_id` и `item_id`. В `item_id` записаны **10 различных ID фильмов через пробел**; уже известные пользователю фильмы исключены.

`sasrec_full.pt` — checkpoint PyTorch: он хранит `model_state`, параметры архитектуры и обучения, число эпох, упорядоченный список ID фильмов, seed, версии библиотек и хеши исходных данных. Приложенные финальные веса содержат **48 эпох**, seed **42** и каталог из **3 706 фильмов**.

Для восстановления весов в тетрадке предусмотрена функция `load_sasrec_checkpoint`. После выполнения ячеек подготовки данных и определения функций SASRec, без запуска ячеек обучения, модель можно загрузить так:

```python
model, checkpoint = load_sasrec_checkpoint(OUTPUT_DIR / 'sasrec_full.pt')
```

Для получения рекомендаций дополнительно нужны исходные истории пользователей и фильтрация просмотренного. Поэтому веса используются вместе с кодом тетрадки и теми же CSV; порядок внутренних ID должен соответствовать checkpoint.
