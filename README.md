# Рекомендации фильмов — HSE RecSys Challenge 2026

Проект для [соревнования HSE RecSys Challenge 2026](https://www.kaggle.com/competitions/hse-rec-sys-challenge-2026).
По истории оценок формируем **10 различных рекомендаций на пользователя**.
Метрика — **Recall@10**; результат для Kaggle — CSV `user_id,item_id`, где во второй колонке 10 ID через пробел.

Сравниваются популярность, ItemKNN, EASE и SASRec. SASRec использует готовую архитектуру
из **RePlay 0.22.0**, обучение реализовано на PyTorch. Жанры, пол и возраст доступны,
но в текущих моделях не используются.

## Результаты

| Модель | Локальный Recall@10 | Подтверждённый Kaggle Recall@10 |
|---|---:|---:|
| Популярность | 0,036167 | — |
| ItemKNN, 100 соседей | 0,055767 | 0,0594 |
| EASE, λ = 1000 | **0,065038** | **0,0860** |
| SASRec | около 0,1415 к концу 50 эпох¹ | — |

¹ Наблюдение по выводу GPU-запуска. Точный максимум и выбранная эпоха
переносятся из `validation_history.csv`; это не метрика тестового CPU-прогона.
EASE превысил `baseline_5 = 0,0821`. Public score SASRec фиксируется отдельно от локальной метрики.
История всех известных экспериментов и численные результаты подбора λ — в [EXPERIMENTS.md](EXPERIMENTS.md).

## Установка

Локально проверяется Python **3.12**. Из корня проекта:

```bash
python -m venv .venv
```

Активация в Windows Git Bash: `source .venv/Scripts/activate`.
В Linux/macOS: `source .venv/bin/activate`.

```bash
python -m pip install -r requirements.txt
```

Для машины без NVIDIA GPU можно сначала установить CPU PyTorch:
`python -m pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cpu`,
затем выполнить установку requirements. В Kaggle сохраняем его CUDA-версию torch.
Точные версии конкретного запуска записываются в отчёт окружения.

## Быстрая проверка одной командой

```bash
python run.py auto
```

Если `outputs/checkpoints/sasrec.pt` добавлен, команда загружает SASRec и создаёт рекомендации
**без обучения**. Если файла нет, она явно сообщает об этом и воспроизводит классические
эксперименты на CPU. Модель, использованная при запуске, печатается в терминале и записывается в JSON.

Явные режимы:

```bash
python run.py baselines
python run.py predict --model ease
python run.py predict --model sasrec
python run.py evaluate
python run.py train
```

- `baselines`: прежняя валидация, популярность, ItemKNN, пять λ EASE и финальный CSV лучшей классической модели.
- `predict --model ease`: фиксированная λ = 1000; EASE быстро рассчитывается по полной истории на CPU.
- `predict --model sasrec`: только загрузка финальных весов и инференс, работает также на CPU.
- `evaluate`: локальный Recall@10 по сохранённому validation-checkpoint, без обучения.
- `train`: полный эксперимент на GPU, выбор эпохи SASRec и переобучение на всей истории.

На выходе — `outputs/submission_sasrec.csv` или `outputs/submission_ease.csv`.
`outputs/submission.csv` — выбранный результат запуска. При полном `train` выбор между SASRec
и классическими моделями производится по локальному Recall@10. Отправка на Kaggle выполняется вручную.

Те же режимы доступны в тетрадке. По умолчанию стоит `MODE = "auto"`.
Тетрадка использует `src/`, поэтому переносить нужно **весь проект**, а не один `.ipynb`.

## Данные и валидация

| Файл | Содержание |
|---|---|
| `events.csv` | user_id, item_id, rating, timestamp; 894 149 событий |
| `user_features.csv` | 6 040 пользователей, пол и код возрастной группы |
| `item_features.csv` | 3 706 фильмов и 18 жанровых индикаторов |
| `submission_sample.csv` | Целевые пользователи и формат ответа |

ID читаются как строки. `timestamp` применяется только для порядка **внутри** пользователя;
это не подтверждённая глобальная временная шкала.
У каждого пользователя последние 20% событий (с округлением вверх) откладываются в validation.
Все остальные события используются для обучения. По умолчанию любая отложенная оценка — target.
Это явно выбранная локальная схема: точный способ скрытия теста организаторами не опубликован в полученной постановке.

Recall@10 — средняя по пользователям доля их целевых фильмов, попавших в top-10.
Считаем по полному каталогу, без sampled negatives. При непустом пороге rating
пользователи без target не входят в среднее. Порог target не меняется при сравнении моделей.
В рекомендациях исключается **вся** известная история, включая низкие оценки и события за пределами окна SASRec.

SASRec обучается по сдвинутым на один фильм последовательностям, с causal attention и полной cross-entropy.
Для длинных историй применяются перекрывающиеся окна. Padding и переход padding → первый фильм не входят в loss.
Лучшая эпоха выбирается по validation. Финальная модель создаётся с нуля и обучается на всех событиях
ровно выбранное число эпох. Валидационный и финальный checkpoint имеют разное назначение.

## Перенос уже обученных весов из Kaggle

В старой тетрадке веса **уже сохранялись**:

- `outputs/sasrec/<идентификатор>/sasrec_full.pt` — финальная модель;
- `outputs/sasrec/<идентификатор>/sasrec_validation_best.pt` — модель для локальной оценки.

Если `sasrec_full.pt` ещё нет, нужно завершить раздел 12 старой тетрадки — переобучение на полной истории.
Не заменяйте его `sasrec_validation_best.pt`: у этих файлов разные обучающие данные.

В исходном Kaggle-ноутбуке выполните одну новую ячейку (переменные старого kernel не нужны):

```python
from pathlib import Path
import zipfile

output_dir = Path("/kaggle/working/outputs")
assert list(output_dir.rglob("sasrec_full.pt")), "Полный checkpoint не найден: завершите раздел 12"
archive = Path("/kaggle/working/kaggle_run.zip")
with zipfile.ZipFile(archive, "w", zipfile.ZIP_DEFLATED) as z:
    for p in output_dir.rglob("*"):
        if p.is_file():
            z.write(p, p.relative_to(output_dir))
print(archive)
```

Скачайте `kaggle_run.zip` до завершения сессии и распакуйте, например, в папку `kaggle_run` рядом с проектом.
Если сессия уже закрыта, используйте сохранённые Outputs версии ноутбука или ранее скачанные файлы.
Если ни weights, ни Outputs не сохранены, восстановить численные веса из одного кода нельзя — потребуется новый train.
Из корня проекта выполните:

```bash
python tools/import_kaggle_run.py --source ../kaggle_run
python run.py predict --model sasrec
```

Минимальный ручной перенос также допустим: `sasrec_full.pt` → `outputs/checkpoints/sasrec.pt`,
а `sasrec_validation_best.pt` → `outputs/checkpoints/sasrec_validation_best.pt`.
Для этого не требуется запускать Python; импортёр ниже дополнительно проверяет содержимое и переносит отчёты.

Импортёр переносит настоящие веса, проверяет ID и совместимость архитектуры,
копирует историю эпох и имеющийся SASRec CSV, сохраняет контрольные суммы.
Он также добавляет точный локальный результат в таблицу README и журнал. Если public score уже известен,
добавьте к команде `--kaggle-score ЗНАЧЕНИЕ` — это должен быть реальный результат именно этого сабмита.
Если в архиве несколько полных моделей, передайте `--checkpoint ПУТЬ_К_sasrec_full.pt`.
Checkpoint старой тетрадки поддерживается напрямую; заново обучать его для смены структуры репозитория не нужно.

Новые запуски сохраняют `model_state`, параметры, порядок ID, выбранную эпоху, seed,
окружение и SHA-256 данных. В checkpoint нет Python-объекта целой модели:
архитектура восстанавливается кодом, затем загружается `state_dict`.
Для текущей конфигурации сам `state_dict` занимает примерно **1,13 MiB**: два финальных `.pt`
можно хранить в обычном Git. Сохранять checkpoint каждой эпохи в репозитории не требуется.

## Kaggle

Загрузите содержимое проекта как Dataset и откройте корневую тетрадку в Kaggle.
Она найдёт `src/` и `config.json` в подключённом проекте. Данные можно брать из его `data/`
или явно указать путь к данным соревнования в `DATA_DIR`.
Результаты записываются в `/kaggle/working/outputs`, а подключённые файлы остаются доступны только для чтения.
При `MODE="predict"` укажите `CHECKPOINT` на подключённый `sasrec.pt`, если он не находится в рабочей папке outputs.
Для полного обучения нужны GPU и доступные зависимости; для EASE GPU не требуется.

## Проверки и воспроизводимость

```bash
python -m unittest discover -s tests -v
python run.py train --smoke
```

Smoke-прогон использует небольшую модель и два батча. Он **не считается экспериментом качества**,
не создаёт сабмит и пишет только в `outputs/smoke/` (эта папка исключена из Git).
Рабочие checkpoints также проходят строгую проверку структуры `state_dict`.
Побитовое равенство GPU-вычислений не требуется; небольшие погрешности сравниваются с допуском.
Между разными GPU/версиями библиотек возможны небольшие различия; точные входные CSV,
порядок ID, конфигурацию и окружение необходимо сохранять вместе с весами.

## Публикация

Перед финальной сдачей добавьте полный checkpoint из Kaggle, точный локальный результат из истории эпох,
SASRec-сабмит и его реальный Kaggle score в журнал. 
По умолчанию `data/` и два финальных `.pt` не исключены из Git; окружение, кэши и smoke-результаты исключены.

Для нового пустого репозитория после копирования его URL:

```bash
git init
git add .
git commit -m "Add reproducible recommendation project"
git branch -M main
git remote add origin URL_ВАШЕГО_РЕПОЗИТОРИЯ
git push -u origin main
```

В уже существующем Git-репозитории повторять `git init` и `git remote add` не требуется.
